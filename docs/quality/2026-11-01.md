# Quality check, 2026-11-01

The ten engineering rules, checked against the code on `main`, with the evidence. Run on Windows 11
with Go 1.26.10 and buf v1.73.0. The race detector needs cgo, which this machine does not have; CI
(Linux) runs `go test -race`.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | fixed | `tickerctl` puts a deadline on every call (`-timeout`, default 10 s, `cmd/tickerctl/main.go`); deadlines and NotFound reach the caller as status codes (`TestErrorsReachTheCaller`). The server stops a stream when the client cancels (`TestServerStreamStopsWhenTheClientCancels`), and `GracefulStop` falls back to `Stop` after 5 s. Every `Send`/`Recv` error is returned. `scripts/get-buf.sh` retried the buf download (`--retry 3`, curl's exponential backoff) but had no time limit; it now passes `--connect-timeout 20 --max-time 300`. No retries in the service, so nothing else to bound. Remaining `_ =` are in tests only. |
| 2 | Writes safe to retry | pass | The service has no writes: all three RPCs read the simulated market. `WatchQuotes` subscribe/unsubscribe is set-based, so a repeated request gives the same set (`apply` dedupes and sorts). The buf download is written to `.part`, checked by SHA-256 and renamed. |
| 3 | No race conditions | pass | `Market.Quote` advances a walk under `mu`; the `walks` map is never written after `New`. The active-stream counter is an `atomic.Int64`. In `WatchQuotes` only the handler goroutine sends; the reader goroutine hands messages over a channel and exits on context cancel. CI runs the tests with `-race`. |
| 4 | Don't trust the clock | pass | Ticks come from `now().Sub(start)` with `now = time.Now` (monotonic, `internal/market/market.go`). Quote timestamps are `start + tick*step`, sent as `google.protobuf.Timestamp` (UTC). Streams pace on `time.Ticker`. |
| 5 | Read before changing | pass | No environment variables are read. `BUF_CACHE_DIR` is set by the Makefile. Every path in the README exists. |
| 6 | Never break compatibility | pass | `ticker.v1` is gated by `buf breaking` against `contract/ticker-v1.binpb` and the base branch; `scripts/breaking-check.sh` proves 4/4 breaking edits are refused and 1/1 compatible edit accepted. The contract did not change. |
| 7 | One source of truth | pass | `gen/ticker/v1` is generated from `proto/` and the drift check fails on any difference. The baseline image is rebuilt only by `make baseline` (ADR 0003). Go 1.26.10, grpc-go v1.85.0, buf v1.73.0 and the generator versions agree across README, `go.mod`, the workflow and `scripts/get-buf.sh`. |
| 8 | Small changes, no secrets, validate input | pass | `git grep -iE "(api[_-]?key\|secret\|token\|password)\s*[:=]"`: no matches. Every request is validated: symbol count, repeats and listing, interval range, `max_updates`, watched-set size, 64 KiB message limit, 256 streams per connection, loopback-only listen address. No new dependency. |
| 9 | Tests that can actually fail | fixed | No `t.Skip`, no assertion-free tests. Mutation check below: 5 of 14 mutants survived; each now has a test that kills it. |
| 10 | Re-verify | pass | `gofmt -l`: empty; `go vet`: clean; `buf lint`, `buf format --diff --exit-code`: clean; generated code: no difference; `RESULT breaking-check: 4/4 breaking changes refused, 1/1 compatible change accepted`; `go test -count=1 ./...`: 18 passed, 4 packages `ok`; the three new tests passed 5 runs in a row; `govulncheck@v1.8.0`: `No vulnerabilities found.`; `audit_repo.py`: OK. CI on push. |

## Mutation check

One hand mutation at a time, `go test -count=1 ./internal/... ./cmd/...` re-run, source restored
afterwards.

Score: 9 of 14 killed before, 14 of 14 after. Each surviving mutant was re-run after its test was
added and the suite failed on it. An equivalent mutant was left out: removing `max(moved, 1)` in
`market.next` cannot change a result, because a move of at most 0.50% with integer division never
takes a positive price below 1.

## Tests added (15 -> 18)

- `TestLimitsAcceptTheirExactMaximum`: 20 symbols, 10 ms and 60 000 ms intervals and
  `max_updates` = 100 000 are accepted; 21 symbols are refused (market with 30 symbols).
- `TestWatchedSetIsCappedAcrossRequests`: 15 + 10 watched symbols is InvalidArgument; swapping 5
  for 10 to reach exactly 20 is accepted.
- `TestWatchIntervalChangeTakesEffect`: no quote arrives during a 60 s interval; after switching to
  10 ms the next event after the acknowledgement is a quote.

## Known limitations

Unchanged from the README: server-side deadlines and bounded per-client buffers are M2, so a
`max_updates = 0` stream runs until the client cancels or its deadline ends it.
